\section*{Abstract}
\addcontentsline{toc}{section}{Abstract}

Automated test generation tools such as EvoSuite and Randoop produce unit tests populated with uninformative identifiers such as \texttt{var0} and \texttt{test42}, which impede comprehension and reduce the practical value of the generated output for the developers who must maintain them.
Renaming these identifiers to meaningful names is a necessary post-processing step, yet existing non-LLM approaches achieve at most $F_1 = 0.308$ and no scalable readability evaluation framework exists. Token-level accuracy and holistic readability are not the same thing: fine-tuning improves $F_1$ to $0.839$ yet simultaneously reduces the LLM readability score, while a zero-shot proprietary model achieves the highest readability of all variants despite a comparable $F_1$, showing that a model can learn to reproduce reference labels without producing names that are more readable to a developer. Neither metric alone is therefore a sufficient ground truth, and both should be reported together when evaluating identifier renaming tools; to support this we contribute \textsc{CodeReader}, a configurable open-source readability grading tool, and demonstrate that even minimal fine-tuning of 15\% of training steps captures most of the token-level benefit.
