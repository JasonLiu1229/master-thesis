\section*{Abstract}
\addcontentsline{toc}{section}{Abstract}

Automated test generation tools such as EvoSuite and Randoop produce unit tests
with uninformative identifiers like \texttt{var0} and \texttt{test42}, which
developers must rename before the tests are practically maintainable. Existing
non-LLM approaches top out at $F_1 = 0.308$, and no established evaluation
framework captures whether renamed tests are actually more readable. We find
that fine-tuning an LLM substantially improves token-level naming accuracy
($F_1 = 0.839$) yet simultaneously \emph{reduces} holistic readability, while a
zero-shot proprietary model achieves the opposite~--- lower $F_1$ but higher
readability~--- demonstrating that these two properties are fundamentally
uncorrelated and that neither metric alone suffices to evaluate identifier
renaming. This divergence means that renaming tools must be assessed on both
dimensions, and we contribute \textsc{CodeReader}, a configurable open-source
LLM-based readability grading tool, to make this dual evaluation reproducible at
scale.
